## Overview

CrewAI can run entirely client-side on [Pyodide](https://pyodide.org), the CPython interpreter compiled to WebAssembly. The `crewai-pyodide` package (in `lib/crewai-pyodide` of the CrewAI repository) installs CrewAI into Pyodide and adapts the runtime: HTTP requests go through the JavaScript `fetch` API, thread pools run their work inline, and native dependencies without a WebAssembly build are skipped.

<Warning>
API keys used in a web page are visible to anyone who can open it. Use this for local tools, demos, or keys your users enter themselves; otherwise send LLM requests through a proxy that holds the key.
</Warning>

## Requirements

- A runtime with WebAssembly JavaScript Promise Integration (JSPI): Chrome or Edge 137+, or Node.js with `--experimental-wasm-jspi`
- Pyodide 0.29 (Python 3.13)
- An LLM endpoint that allows cross-origin requests, such as the OpenAI API

## Build and run the example

From a checkout of the CrewAI repository:

```bash
uv run python lib/crewai-pyodide/build.py
python -m http.server -d lib/crewai-pyodide/dist
```

Open `http://localhost:8000`, enter an OpenAI-compatible endpoint and API key, and run a two-agent crew in the page.

## Use it in your own page

Serve `dist/crewai-pyodide.mjs` and `dist/wheels/` with your page, then:

```js
import { loadCrewAI } from "./crewai-pyodide.mjs";

const pyodide = await loadCrewAI({ wheelBaseURL: "./wheels/" });
pyodide.globals.set("api_key", apiKey);

const answer = await pyodide.runPythonAsync(`
import crewai_pyodide
from crewai import LLM, Agent, Crew, Task

llm = LLM(model="gpt-4o-mini", api_key=api_key)
agent = Agent(role="Writer", goal="Write haiku", backstory="A poet", llm=llm)
task = Task(description="A haiku about WebAssembly", expected_output="A haiku", agent=agent)

result = await crewai_pyodide.run(Crew(agents=[agent], tasks=[task]).akickoff())
result.raw
`);
```

<Note>
Always use the async entry points (`crew.akickoff()`, `flow.kickoff_async()`, `llm.acall()`) and wrap them in `crewai_pyodide.run()`. Pyodide's event loop is always running, so the synchronous `kickoff()` refuses to start.
</Note>

## What works

- Agents, Tasks, Crews and Flows
- The native OpenAI provider and OpenAI-compatible endpoints via `base_url`, including streaming and native tool calling
- Custom tools that do not need native code; `requests` works, `urllib.request` does not

## Limitations

- Memory, Knowledge and RAG are unavailable: their default storage (LanceDB, ChromaDB) has no WebAssembly build. Flows run without their automatic memory.
- MCP servers over stdio, subprocess-based code execution, and most `crewai-tools` packages do not work.
- Async tasks and tool calls run one at a time rather than in parallel.
- Telemetry, tracing and the update check are disabled.
