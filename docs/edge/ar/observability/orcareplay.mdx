# سجّل طاقمك وأعد تشغيله

[OrcaReplay](https://github.com/Continuum-AI-Corp/OrcaReplay) هو أداة تنقيح مفتوحة المصدر للوكلاء
تعتمد على التسجيل وإعادة التشغيل. يسجّل التشغيل في ملف على القرص، ثم يعيد تشغيل ذلك الملف مع تقديم
ردود النموذج من التسجيل نفسه — فيتكرر التشغيل ذاته تمامًا، دون اتصال، بقدر ما تشاء، ودون إنفاق أي
رموز.

هناك فارق عن بقية الأدوات في هذا القسم يستحق معرفته قبل المتابعة: **لا شيء يُضاف إلى شيفرتك.** لا
SDK ولا callback ولا decorator ولا `import`. يشغّل OrcaReplay سكربتك ويلتقط حركة الشبكة التي تمر
من تحته.

## البدء

```bash
pip install crewai
npm install -g orcareplay
```

شغّل طاقمك كما تفعل عادة، مع وضع `orca record` قبله:

```bash
orca record generic-openai -- python your_crew.py
```

هذا هو التكامل بأكمله. وعند الانتهاء:

```bash
orca show last        # الخط الزمني: كل طلب واستجابة واستدعاء أداة ونتيجتها
orca replay last      # التشغيل نفسه مرة أخرى — من التسجيل، دون استدعاء النموذج
```

## ما الذي يُلتقط

واجهات النماذج عديمة الحالة، لذا يعيد الطاقم إرسال المحادثة كاملة في كل دور — بما في ذلك نتائج
الأدوات من الدور السابق. ولهذا فإن وسيطًا أمام النموذج يرى الحلقة كاملة، لا استدعاء النموذج وحده:
كل طلب، وكل استجابة متدفقة، وكل استدعاء أداة أصدره النموذج، وكل نتيجة أداة أنتجها طاقمك.

```console
$ orca show last
run_0ec7e5de1f25  generic-openai@0.2.3  6 events  exit 0

SEQ  KIND   WHAT                                           DETAIL
0    RUN    run started                                    generic-openai
1    SNAP   tree ee2d5836718ef5ac09bfc73e3b3d4c7e6f27cf93   0 changed
2    MODEL  gpt-4o-mini                                    1 messages
3    MODEL  gpt-4o-mini                                    stop: end_turn · 9 in · 4 out
4    SNAP   tree ee2d5836718ef5ac09bfc73e3b3d4c7e6f27cf93   0 changed
5    RUN    run ended                                      exit 0
```

هذا طاقم بوكيل واحد ومهمة واحدة. أما الطاقم الذي يستخدم أدوات فتظهر فيه صفوف `tool.call` و
`tool.result` بين صفوف النموذج، مُعاد بناؤها من المحادثة التي أعاد الإطار إرسالها — وهكذا تصبح
الحلقة كاملة مرئية لشيء لم يرَ سوى HTTP.

وإلى جانب حركة النموذج، يسجّل تغييرات الملفات في كل دور، وأوامر الصدفة مع رموز خروجها ومددها
الحقيقية.

## إعادة التشغيل، والتفرّع من خطوة معيّنة

إعادة التشغيل هي الجزء الذي ليس مراقبة. التسجيل ملف، لذا فإن تشغيلًا التقطته الأسبوع الماضي يتكرر
اليوم والشبكة مغلقة:

```console
$ orca replay last
info replaying run=run_0ec7e5de1f25 exchanges=1 egress=blocked
info replay.done reused=1/1 exact=1 divergences=0 unmatched=0 exit=0
```

تنطبق `egress=blocked` على حركة النموذج: يرفض الوسيط تمرير أي شيء لا يستطيع تقديمه من التسجيل، فلا
يُستدعى شيء ولا يُنفق شيء. غير أن إعادة التشغيل ما تزال *تنفّذ استدعاءات الأدوات المسجّلة فعليًا* —
فأي أداة تفتح مقبسها الخاص تصل إلى الشبكة — ولذلك فإن إعادة التشغيل ليست بيئة معزولة.

والتفرّع هو النصف الآخر. خذ التسجيل حتى نقطة تفتيش، ثم تابع مباشرةً على نموذج مختلف:

```bash
orca replay last --from 4 --model gpt-5.2
```

المهمة نفسها، وبادئة المحادثة نفسها، والملفات نفسها، ونموذج مختلف ابتداءً من الخطوة 4 — وهذا ما
يجعل المقارنة بين نموذجين ذات معنى. هذا الجزء يستدعي النموذج فعليًا ويستهلك رموزًا.

## توجيه الطاقم إلى المسجّل أو إلى بوابة

يضبط `orca record generic-openai` كلًّا من `OPENAI_API_BASE` و`OPENAI_BASE_URL`، والمزوّد الأصلي في
CrewAI 1.x يقرأ كليهما — ولهذا لا يحتاج الأمر أعلاه إلى وسائط ولا إلى تعديل طاقمك. كما يعمل تمريره
في الشيفرة عبر `LLM(base_url=…)`؛ غير أن متغيرات البيئة هي المسار الذي يهيّئه `orca record` أصلًا.

وثمة أمر ينبغي معرفته عند استخدام اسم نموذج لم ينشره المزوّد — وهو ما يعنيه عادةً توجيه طاقم إلى
بوابة. قيس هذا على **crewai 1.15.20**:

| `LLM(model=…)` | يُحَلّ |
|---|---|
| `gpt-4o-mini`، `my-gateway-model` | دائمًا — الاسم بلا بادئة يصل إلى المزوّد الأصلي أيًّا كان |
| `openai/gpt-4o-mini`، `openai/o3-mini` | دائمًا — يتكفّل به مزوّد أصلي |
| `openai/my-gateway-model` | **فقط حيث يكون LiteLLM مثبّتًا** |

الاسم ذو البادئة الذي لا يتكفّل به أي مزوّد أصلي يسقط إلى LiteLLM، و1.x لا يثبّته افتراضيًا
(`crewai[litellm]` يضيفه). لذا يعمل السطر نفسه على جهاز ويثير على آخر
`ImportError: … and the LiteLLM fallback package is not installed`. واستخدام الصيغة بلا بادئة
لأسماء نماذج بوابتك يتفادى المسألة كليًا.

ويقع الخطأ أثناء إنشاء كائن `LLM`، قبل أي طلب — فيحتوي تسجيل ذلك التشغيل على ثلاثة أحداث فقط
ويبلّغ OrcaReplay عن `capture.empty`، وهو تقرير دقيق يسهل قراءته كمشكلة التقاط بينما هو مشكلة اسم
نموذج.

## القياس عن بُعد اتصال منفصل

يرسل CrewAI بيانات القياس الخاصة به، وهي ليست حركة نموذج ولا تُلتقط هنا. فإن أردت ألا يتحدث
التشغيل إلا مع المسجّل:

```python
import os

os.environ["CREWAI_DISABLE_TELEMETRY"] = "true"
os.environ["OTEL_SDK_DISABLED"] = "true"
```

اضبطها قبل استيراد `crewai` — إذ يُهيَّأ عميل القياس عند الاستيراد.

## متحقَّق منه في التكامل المستمر

لدى CrewAI فحص خاص به ضمن مصفوفة تكامل OrcaReplay: `Agent` و`Task` و`Crew` حقيقية تُسجَّل مقابل
مصدر اختباري، ثم يُوقَف المصدر، ويُعاد تشغيل التسجيل دون اتصال.

```
── crewai            1 exchanges, replayed exact with the origin down
```

يعمل هذا الفحص مع كل commit، فالادعاء الذي تقدّمه هذه الصفحة يُسقط البناء بدل أن يتقادم بصمت.
والفحص هو
[`test/integrations/agents/crewai_agent.py`](https://github.com/Continuum-AI-Corp/OrcaReplay/blob/main/test/integrations/agents/crewai_agent.py).
