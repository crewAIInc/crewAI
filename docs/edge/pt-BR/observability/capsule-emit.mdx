# Visão Geral do Agent Action Capsule

O [capsule-emit](https://github.com/action-state-group/capsule-emit) registra cada chamada de ferramenta em uma execução de crew como uma cadeia de **Agent Action Capsules**: uma cápsula *planejada* selada quando a chamada inicia e, ao terminar, uma cápsula *confirmada* (ou *com erro*) selada e encadeada à planejada pelo id da cápsula. Cápsulas são evidência de auditoria e conformidade do que a crew realmente fez — complementares ao rastreamento.

Duas camadas de verificação, deliberadamente distintas:

- **Offline, `verify()`** checa estrutura, endereçamento por conteúdo (cada digest é recalculado a partir do próprio conteúdo do registro) e consistência da cadeia — sem serviço, sem credenciais.
- **Evidência de violação perante um terceiro** vem da etapa de ancoragem: os digests das cápsulas são registrados em um log de transparência SCITT, e o recibo do log é o que torna alterações posteriores evidentes para alguém fora do seu ambiente. O quickstart executa essa etapa contra um serviço stub local para manter a demo hermética; a ancoragem em produção aponta para um log real.

### Recursos

- **Um listener, todas as chamadas de ferramenta**: registre `CapsuleEventListener()` uma única vez pelo mecanismo padrão `BaseEventListener` do CrewAI — sem alterações de código por ferramenta.
- **Cadeias planejado → confirmado**: uma cápsula planejada é selada quando a chamada de ferramenta inicia; ao terminar, uma segunda cápsula confirmada é selada e encadeada a ela (`prior_capsule_id`); erros selam uma cápsula de efeito falho encadeada.
- **Privacidade somente por digest**: entradas/saídas das ferramentas são registradas como digests SHA-256 — o conteúdo bruto permanece local; apenas digests são ancorados.
- **Checagens de consistência offline**: `verify()` reverifica estrutura, endereçamento por conteúdo e elos da cadeia apenas a partir do registro.
- **Evidência de violação ancorada**: registro somente por digest em um log de transparência SCITT; o recibo é a etapa central da evidência de violação independente.
- **Seguro para a crew por construção**: o listener respeita `is_replaying()` e nunca lança exceções na execução da crew; uma âncora inacessível não pode quebrar a crew.

## Instruções de Configuração

<Steps>
    <Step title="Instale o capsule-emit com o extra do CrewAI">
      ```shell
      pip install "capsule-emit[crewai]"
      ```
    </Step>
    <Step title="Registre o listener">
      ```python
      from capsule_emit.adapters.crewai_listener import CapsuleEventListener

      # Register once, before kickoff — every tool call in the crew seals a capsule.
      listener = CapsuleEventListener()
      ```
    </Step>
    <Step title="Execute sua crew normalmente">
      ```python
      result = crew.kickoff()
      ```
      Cada chamada de ferramenta agora produz registros selados no ledger local (`ledger.jsonl` por padrão), com digests ancorados no serviço de transparência SCITT configurado.
    </Step>
    <Step title="Confira a evidência">
      ```python
      import json
      from agent_action_capsule import verify

      rows = [json.loads(line) for line in open("ledger.jsonl") if line.strip()]
      ok = all(verify(row.get("capsule", row)).ok for row in rows)
      print(f"{len(rows)} capsules, verify: {'ALL OK' if ok else 'FAILURES'}")
      ```
    </Step>
</Steps>

## Quickstart executável

Uma demonstração hermética de ponta a ponta acompanha o pacote (event bus real do CrewAI, serviço de transparência stub local, sem chave de LLM e sem serviço externo):

```shell
pip install "capsule-emit[crewai]"
python examples/crewai-listener/demo.py
```

## O que é registrado

| Campo | Conteúdo |
|---|---|
| `action_id` / nome da ferramenta | qual chamada de ferramenta esta cápsula registra |
| digests de entrada/saída | compromissos SHA-256 — o conteúdo bruto nunca sai do seu ambiente |
| `effect` | `planned`, `executed`, `confirmed` ou `errored` |
| cadeia `confirms` | a cápsula executada cita a cápsula planejada por endereço de conteúdo |
| recibo de âncora | registro somente por digest em um log de transparência SCITT (opcional, ativado por padrão) |

O formato do registro é uma especificação aberta (`draft-mih-scitt-agent-action-capsule`, um Internet-Draft individual do IETF) com implementação de referência Apache-2.0.
